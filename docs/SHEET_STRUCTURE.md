## index.js 재작업 시 참고할 핵심 포인트

1. **"권한관리"→"데이터" 열 매핑**: 옛 `A1:H50`, `row[1]`=번호, `row[2]`=이름, `row[3]`=이메일 → 새 "데이터"에서도 **동일 인덱스(B/C/D열)** 이므로 시트 이름만 바꾸면 `listAllMembers()`/`findMemberNumberByEmail()`은 거의 그대로 이식 가능. 단, D열(이메일)이 현재 비어있어 실사용 검증 시 문제가 될 수 있음.
2. **"제보상점"→"데이터" R~V 슬롯**: 옛 `D~J`(요일별)+`K`(총점)+`L`(벌점) 구조가 완전히 사라지고 `R~V`(1~5차 슬롯, 사이클 번호 기록) 방식으로 바뀜 — index.js의 `getMerit`류 함수는 로직 자체를 새로 짜야 함(단순 열 이름 치환 불가).
3. **개인 탭 행 번호 대량 이동**: C38(교시참여율)은 안 바뀜, 하지만 옛 C39(누적송출P)/C40(금주달성P)/C41(누적달성P) 개념 자체가 사라지고 새 C39(페널티표시)/C40(일반반휴잔여)/C41(사유반휴잔여)/C42(참조행번호)/C43(감사행번호)로 전면 재배치됨. index.js의 `ROW_OUTPUT_PEN_CUMUL=38`, `ROW_TIME_PEN_THISWEEK=39`, `ROW_STUDY_TIME_MERIT=35`, `ROW_REPORT_MERIT=36`, `ROW_REPORT_SHEET_ROW=37` 등 0-index 상수들이 전부 이 최신 배치 기준으로 재계산되어야 함.
4. **`_exit_define()`/`_set_sheet_init()`가 만드는 "이름 (퇴실)"/"이름 (재납)" 백업 사본**은 "데이터 (감사)"를 참조하도록 수식이 치환됨(C42→C43, `'데이터'`→`'데이터 (감사)'`) — index.js가 이 백업 사본을 읽는 로직이 있다면 동일하게 대응 필요.
